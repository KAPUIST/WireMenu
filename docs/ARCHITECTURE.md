# 코드 구조와 검증 기준

코드 확인 기준: 2026-09-15. 구현을 다시 설명하는 API 목록 대신 수정 위치와 회귀 위험을 기록한다. 심볼·호출 관계는 Swift 소스와 `rg`로 확인했다.

## 어디를 수정할까

| 변경 대상 | 시작 파일 | 역할 |
| --- | --- | --- |
| 앱 시작 | `Sources/WireMenu/main.swift` | NSApplication과 AppDelegate 연결 |
| 메뉴바 색·아이콘, 창 위치·열기·닫기 | `Sources/WireMenu/AppDelegate.swift` | 상태 아이템, 패널 수명, 이벤트 모니터, 화면 좌표 |
| 연결 분류·인터페이스 선택 | `Sources/WireMenu/ConnectionKind.swift` | NWPath를 표시 상태로 변환, 기본 IPv4 인터페이스 참고 |
| 네트워크 변경 감지 | `Sources/WireMenu/NetworkMonitor.swift` | NWPathMonitor 이벤트를 메인 큐로 전달 |
| Wi-Fi 검색·연결, 권한, 전송량 | `Sources/WireMenu/NetworkPanelModel.swift` | CoreWLAN·CoreLocation·Keychain·SMAppService와 화면 상태 연결 |
| 메뉴 디자인·목록·그래프·키보드 이동 | `Sources/WireMenu/NetworkPanelView.swift` | SwiftUI 뷰, 행 스타일, 경량 Path 그래프 |
| Finder 앱 아이콘·번들 | `App/generate-icon.swift`, `App/Info.plist` | 빌드용 아이콘 생성과 앱 설정; 메뉴바 아이콘과 별개 |

## 연결 상태의 흐름

```text
NWPathMonitor → ConnectionSnapshot → AppDelegate.apply
                                      ├─ 메뉴바 아이콘
                                      └─ NetworkPanelModel → NetworkPanelView
CoreWLAN 신호 변경 → 공유 신호 강도 ────┴─ 메뉴바와 현재 Wi-Fi 행에 반영
```

- 경로가 불통이면 오프라인, 이후 유선·핫스팟·Wi-Fi 순으로 분류한다. 핫스팟은 cellular 또는 expensive Wi-Fi라는 휴리스틱이다. USB 테더링은 유선으로 분류될 수 있다.
- 모델의 메타데이터 큐는 IP와 링크 정보를 읽는다. `metadataGeneration`은 이전 연결의 늦은 결과가 새 상태를 덮는 것을 막는다.
- Wi-Fi 검색·연결은 직렬 작업 큐를 사용한다. 검색 결과는 `scanGeneration`과 전원 상태를 확인한 뒤 반영한다. 이 검사를 없애면 이전 검색 결과가 다시 나타날 수 있다.
- 검색 결과는 SSID별 가장 강한 항목을 남기고 알려진/현재 네트워크와 나머지를 나눈다. OS의 저장된 네트워크 전체 목록을 그대로 복제하는 것은 아니다.

## 메뉴와 리소스 수명

- `showPanel()`은 모델을 갱신하고 패널·크기 관찰·입력 이벤트 모니터를 연결한 뒤 전송량 수집을 시작한다.
- `closePanel()`은 관찰·이벤트 모니터·수집 타이머를 해제한다. 그래프는 닫기 애니메이션 동안 유지하고 완료 후 비운다.
- 닫히는 창과 새 창의 동일성 검사를 유지한다. 이전 창의 지연된 닫기 콜백이 빠르게 재열린 새 창을 닫지 않아야 한다.
- 전송량은 인터페이스 누적 바이트의 시간차로 계산한다. 카운터 초기화·인터페이스 변경 시 기준값을 재설정하고 기록은 최대 60개로 제한한다. 별도 그래프 라이브러리나 상시 디스크 기록은 없다.
- `getifaddrs` 결과는 `freeifaddrs`로 해제한다. 배열 제한만으로 앱 전체에 누수가 없다고 판단할 수는 없다.

## UI 변경 시 유지할 기준

- 현재 연결을 맨 위에 두고 업로드·다운로드는 분리한다. 화면에 들어가는 동안 아래로 늘리고 한계를 넘을 때 스크롤한다.
- 창은 현재 메뉴바 버튼과 해당 화면의 좌표를 사용한다. 모니터를 이동·분리한 뒤에도 예전 캡처 좌표를 재사용하지 않는다.
- 마우스로 열었을 때 불필요한 포커스 테두리를 숨기되 키보드 이동·접근성은 유지한다. 동작 줄이기 설정을 존중한다.
- 비활성 메뉴바 색은 비템플릿 SF Symbol과 동적 시스템 색을 조합해 보정했다. 단순히 `isTemplate = true`로 되돌리면 과도한 흐림이 재현됐다. 불투명도는 macOS 26 실측 보정이지 Apple 공식 상수가 아니다.
- 앱 아이콘은 빌드 시 생성한다. 사용자 취향의 디자인 변경과 성능 최적화를 한 작업에 섞어 광범위하게 재작성하지 않는다.

## 검증 범위

표준 자동 검증은 README의 `swift test`와 빌드 명령이다. UI는 별도 검증이 필요하다.

| 변경 영역 | 추가 확인 |
| --- | --- |
| 창·애니메이션 | 메뉴가 아래로 열림, 헤더 고정, 하단 잘림 없음, 펼치기와 접기, 빠른 재열기, Esc/바깥 클릭 닫기 |
| 아이콘·색 | 활성/비활성 모니터, 밝고 어두운 외관; 같은 시점·배경의 기본앱과 비교 |
| 연결·신호 | 메뉴바와 현재 행의 상태 일관성, 오래된 비동기 결과 폐기; 실제 연결 전환은 사용자 요청 범위 확인 |
| 전송량·메모리 | 반복 열기/닫기 전후 같은 측정 도구·조건 사용, 열린 상태/닫힌 상태 구분, 기록·타이머 수명 확인 |

`Tests/check-panel.applescript`는 네트워크를 바꾸지 않는 UI 검사다. `Expanded list: false`는 목록 검사 생략이며 전체 UI 통과가 아니다. `Tests/check-menu.applescript`는 실제 Wi-Fi 연결과 검색 권한이 있어야 알려진 네트워크의 재열기 표시를 검사할 수 있다. 항목 인덱스로 네트워크 버튼을 임의 클릭하지 않는다.

## 알려진 한계와 다음 확인

- **신호 칸수:** RSSI 임계값은 추정이다. −62dBm에서 기본앱 3칸을 관측한 적은 있지만 전체 전환 경계·OS 버전별 차이는 미검증이다. 장기 비교 로그 수집은 시작하지 않았다.
- **핫스팟:** 실제 핫스팟 연결 전환 검사는 미실시다. expensive 경로 판별과 Instant Hotspot 주변 기기 검색은 서로 다른 기능이다.
- **누수 의심:** 2026-09-14 메뉴 20회 열기/닫기 후 `leaks`의 CWConfiguration 의심 객체가 21개·672바이트 늘었고 physical footprint는 약 32.1→32.8MB였다. 도구 접근 제한이 있어 정확한 원인·장기 증가율은 미확정이다. `knownSSIDs(for:)`의 설정 조회가 조사 시작점이며, Apple 문제나 앱 무누수로 단정하지 않는다. 아직 수정하지 않았다.
- **검증된 범위:** 기준일에 단위 테스트 8개·릴리스 빌드·서명 검사를 통과했다. 실제 GUI·구형 macOS·장기 메모리 안정성을 모두 보증하는 결과는 아니다.
